# 反模式与真实教训

每条都是踩过的：症状 → 原因 → 怎么做。协议字段的逐条消费注意见
[daemon-protocol.md](https://github.com/Windsland52/maafw-live/blob/main/docs/daemon-protocol.md)
与[留存契约 §7](https://github.com/Windsland52/maafw-live/blob/main/docs/keyframe-retention-contract-v0.md)。

## 1. 判定与结果消费

| 症状 | 原因 | 怎么做 |
| :--- | :--- | :--- |
| "任务成功了"但游戏没动 | 拿退出码或信封外层 `ok` 当业务结果 | 任务级结果只看 `data.record.ok`；`record.nodes[]` 看每节点状态 |
| 看不出走了哪条分支 | 节点名只说明"执行了哪个节点"，不说明"当时有哪些出口可选" | 看 `record.nextCandidates`（轮询序列，`polls` 是同一候选被轮询的次数）+ `record.nodes[].name`（权威档）：前者是候选，后者是结果 |
| `record.nodes[].name` 两次同名、看不出走了哪条分支 | 框架在 `PipelineNode.*` 顶层填的是**任务入口名**；工具已改为优先取内嵌 `node_details.name`，并用 `nameSource` 标注来源 | 按 `nameSource` 判：`node_details` = 权威；`entry` = 顶层兜底、**未确认**（节点还没跑完时会出现），这时别拿它当"跑了哪个节点"，用屏幕/留存帧复核 |
| 识别"命中"了，框却是全零 | miss 时框架仍回 detail 对象 | 只认 `hit`；零尺寸 box 一律当未命中 |
| 任务失败但退出 0 | 旧版 CLI 按外层 `ok` 定退出码（已修） | 现在 `record.ok=false` → 退出 1；仍要按字段判定，不要只信码 |
| 把 `FINDINGS(3)` 当失败 | 3 的语义是"跑成了，但发现了问题" | 未命中、裁剪警告、帧不可解析都属此类；按 `error.code` 分支 |
| 节点事件对不上画面 | 节点事件的 seq 是**回调时最新帧序**，且可能被后续回调更新 | 关联强度按 `adjacent` 计；转移级结论不能只靠邻近帧 |
| `startSeq` 当"开跑前截图" | 它不是严格的开跑前截图，`framesCaptured` 是进程累计值 | 要"动作前/后"的画面就用 `input` 返回的 `retention.before/after` |

## 2. 会话与生命周期

- **同一台设备并发两个控制器**（面板 daemon + 一次性命令 / 两个终端）= 互扰，属红线。要并发就换设备或串行化。
- **一次性命令的环是空的、`seq` 恒为 0**：每次命令 spawn 自己的 daemon，连接与帧流都是进程态。
  帧序对齐、历史帧取用、`reco --seq` 只在 `repl` / 客户端订阅路径有效。
- **命令退出即断开**：一次命令里想"连接 → 看 → 点 → 再看"，必须写进同一个 `repl` 会话（或客户端脚本）。
- **"另一个时刻"冒充不了"当时那一次"**：`screencap` 拿的是现在；已淘汰的 L0 帧就是没有了——
  升格失败要如实接受，改走 L1 参考帧并说明它不作证据本体。
- adb 的 `destroy` 偶发阻塞：客户端超时后会硬杀 daemon 自愈，这属预期，不是崩溃。

## 3. 坐标与图像空间

- **历史帧 roi 必须按该帧捕获时尺寸换算**（每帧带 `fw/fh`）。按当前全局尺寸换算会在重连/改分辨率后静默错剪。
- **L1 小图上的 box 不是 pipeline 坐标**：小图空间 → 控制器空间要换算；识别单测用小图时结果要标注来源尺寸。
- **`--short-side` / `--long-side` / `--raw` 只在手动连法生效**；项目模式按 `interface.json` 的
  `display_short_side` 走。改了缩放，项目里所有 roi 与模板都要重算。
- **模板空间 = 源帧捕获时尺寸**。从旧帧裁的模板用在当前空间会失效——裁剪结果里的 `spaceCheck.match:false`
  就是这个信号（工具同时会警告并退出 3）。
- 模拟器上 `adb shell wm size` 改物理分辨率**不传导**到框架截图（实测 MuMu：原生 screencap 已变，
  控制器仍按初始化尺寸交付）。要触发分辨率变化，用重连改 `shortSide`。

## 4. 识别与模板

- **未命中先问"目标在不在帧里"**，再谈 roi / 阈值 / 模板。得分 < 0.5 是"不匹配"，不是"阈值太高"。
- **纯色/低纹理模板的得分是噪声**：CCOEFF_NORMED 下大面积同色会让 best 落到别处且得分不低。
  判据是**位置正确优先于得分**——`positionOk:false` 的模板不要用。
- **参数用例别只测一档**：同一模板在不同阈值/roi 下表现差很多；`--sweep` 出曲线再定起点（实测 − 0.1）。
- **SoM 候选表是"截断表"，不是"全部区域"**：候选上限 30，实测 6 帧里 4 帧打满、去重后真实规模中位 54
  （默认上限只放出约 41%）。没出现在表里 ≠ 画面上没有那个东西；回执里 `mergedTotal` 与 `count` 不等就是截断了。
  截断**按横向分带轮转**（带内保持源优先级），所以不会出现"某一段整体消失"的假象——
  **若某个带确实为 0，那是供给真的没有**，不是被截掉的。
- **别把"表里没有"当成"那里不能点"**：候选表要按源理解——OCR 框贴文字、连通域偏亮连通区、
  边缘密度看梯度；暗底图标、无文字的纯色按钮可能任何源都不给。找不到就走点选路径（`crop --point`）。
- **别指望 edge 源，也别去调它**：实测把边缘门槛放松（z 1.2→0.6、地板 2000→600）后，edge 的**独立候选反而
  更少**（17→15）——阈值一松，热块聚成更大的边缘簇，然后被优先级更高的连通域在合并阶段吸收掉；
  覆盖率上升只是框变大。暗底、无文字的按钮该走点选路径（`crop --point`），不是调阈值。
- **`annotate --from-kf` 没有 diff 源**：库帧路径没有会话事件，工具如实报 `sourcesUnavailable.diff`。
  要看"哪里变了"必须用实时会话的 `annotate`（配 `stream` 的变化事件），库帧路径只回答"画面里有哪些区域"。
- **`positionOk` 不是"框完美"的证明**：它只说明"模板在同帧上落回你给的那块区域"（IoU 重叠判据）。
  宽松框给太大时 snap 会偏，而它照样为真——实测图鉴图标 110×110 输入、snap 收到 57×69，真值是 69×62，
  宽度少了 12px，`positionOk` 却是 `true`。要判框准不准：**给贴边的框**，或再裁一遍比 `box` 变化。
- **动态区域模板跨帧不稳**：同帧自匹配 1.0 只证明"模板与源帧一致"；要在新帧上复测（`crop` 自动做跨帧验证）。
- **不要凭直觉调 snap 常数**（`snapTol` / `snapFrac`，默认 90 / 0.12）：36 例 A/B 实测，把阈值调"敏感"
  （60 / 0.2）会让 snap 更勤快（触发 61%→69%）却让**位置正确率从 91.7% 掉到 83.3%**——过度收紧后，
  候选池的外扩档会落到更不独特的区域。默认值不是随手写的，改之前先跑 `npm run survey:crop` 拿数据。
- **塌陷不是失败**：snap 把框收到原面积 35% 以下时，只要 `positionOk` 为真就照用——同一批数据里塌陷例
  位置全部正确。反过来，**耗时翻倍才是警告**：健康区域 9 次评估 ≈10s，退化区域 17-21 次 ≈20s。
- **从降采样小图裁模板**（或上采样冒充原图）会得到尺寸对不上的模板：模板尺寸必须与识别空间一致。

## 5. 留存与关键帧库

- **攒到最后再升格**：L0 是有界 FIFO，等这段做完，那次捕获早已淘汰——一次性状态就此没有证据。
- **升格要在捕获它的那个 daemon 会话里做**：换个进程的 L0 是空的。
- **库副本按单写者管理**（v0）：同 ID 冲突内容必须报错，不能任选一份；复制库保留身份，新建库生成新身份。
- **裸序号不是引用**：`kf:0142` 只能当展示简称，跨库持久引用要完整 `kf:<库UUID>:<序号>`。
- **库配额满额是拒绝新增并报告**，不后台静默删除已升格帧——清理策略由人决定。
- **L2 出处别漏**：模板提交进仓库时带上 `<out>.prov.json`；脱敏裁剪可能去掉识别上下文，
  裁后要重核 hits/box 断言，不要继承原图的全部验证结论。

## 6. 框架原生坑（会崩，不只是结果不对）

- **节点回调里禁止发任何控制器任务**（截图/点击）。实测：`add_sink` 回调中并发 `post_screencap` 与识别回路
  抢控制器，触发原生崩溃 `0xC0000005`（同任务关/开必现对照）。要用帧就读 `cached_image`（识别回路自己截的图，
  零新任务），并按 `adjacent` 报关联强度，不冒称 `bound`。
- **agent 子进程与 maa-node 必须同版本**（协议号握手）：通道能建立但握手被拒——连接后要复核
  `connected && alive`，不能只看"没报错"。
- 无效模板会让 beta 绑定原生崩溃：识别单测在**一次性子进程**里跑，子进程炸掉只损失一次测试。

## 7. 本工具的已知边界（会随时间收敛，遇到先按"如实报告"处理）

- 自匹配要加载资源：`crop` 必须能解析到资源目录（`--project` 或 `--resource-dir`）；
  库帧路径可以用 `--project` 离线解析资源（不连设备）。
- 裁剪耗时（实测口径，别按"卡死"处理）：健康区域 **9 次评估 ≈10.5s**，退化区域 **17 次 ≈20s**；
  同元素在 1920×1080 上同样 9 次、11.9s（+13%）。**耗时翻倍本身就是"这块内容不独特"的信号**。
- 库帧路径的跨帧验证**缺省关闭**是有意的：留存帧对应的状态通常已不在画面上，硬比会产生假警告。
- 修过的两个静默错误（避免旧印象）：解码后未归一化 RGB 会导致 RGBA 帧错剪；多条裁剪警告曾互相覆盖，
  现在回执给 `warns[]`。
