## 1. 核查基线与结论

本仓 commit `85dae0e7f075f9e9eb6af3253759d7050d88a5e1`（重构前基线），核查时工作树干净。已实现“常驻设备会话＋降采样帧环＋同源节点事件”，**未实现耐久关键帧库**。主契约中的 L0 原图缓存、稳定 ID、升格与解析均为待补能力。

| 能力 | 已核查行为 | 对齐影响 |
| --- | --- | --- |
| 会话 | 单 daemon 持有一个 Controller / Resource / Tasker | 宿主保持生命周期及设备独占，不另开采集链 |
| 采样 | 默认动态 8fps，稳定后约 1Hz | 可在 LLM 思考期间继续采样，但不保证捕获全部瞬态 |
| 帧环 | 默认 120 帧、可设 20–600；长边默认 480；FIFO | 仅保留小图，无同次捕获原图留存 |
| 预览 | preview.png 原子替换 | 固定路径不是稳定帧身份 |
| frame_get | 指定 seq 导出尚存小图，支持 roi / out | 可复用导出机制，但不能恢复已丢弃原图 |
| screencap | 另拍控制器分辨率 PNG，无 seq / t | 是另一次捕获，不能补回消失状态 |
| input | 返回 ok / kind / ms | 无动作 ID、前后图关联，不触发抓帧或提频 |
| 节点事件 | 回调时记录最新 S.seq | 时间邻近，不是引擎识别图的精确绑定 |
| 重生 | 超时杀进程、下次调用重生，需要重新 connect | 不恢复帧环、资源、现场或 checkpoint |

裸 seq 重启归零，同进程重连又可能混入旧帧；客户端元数据存在也不代表像素仍可取。历史 ROI 用当前全局 fullW/fullH 换算，缺少每帧原尺寸。主契约据此要求完整捕获身份及 per-frame 坐标依据。

## 4. 原始讨论与合并裁决

- 2026-09-11 的讨论提出常驻帧流、变化检测与环形缓冲，支持等稳定和历史回看。
- 2026-09-12 定案废弃独立轨迹层，改为帧流＋节点事件同源；本次不重新建设全量轨迹系统。
- 早期评估曾否决独立 CLI，但当前仓库已提供 CLI；接口以当前代码为准。

并行草案已收敛：

| 分歧 | 采用方案 | 理由 / 边界 |
| --- | --- | --- |
| 小图是否可作正式 state 证据 | 保留主契约的严格 L0-only 策略 | L1 仅参考，不自动满足正式证据门；未声称这是所有观测场景唯一选择 |
| checkpoint 是否改名 focus | 保留 checkpoint，收窄为开发断点 | 不为概念澄清引入额外字段迁移；本地现场单独确认 |
| 自动留存还是人工升格 | 自动入有界锚区，显式升格 | 沿用最新草案的责任划分；仍有等待过久被淘汰的边界 |
| 裸 kf 序号 | 补库 UUID，完整 ID 不透明 | 防止不同库同序号误解析；副本 v0 不支持多写者合并 |
| 事件 seq 能否证明当前位置 / 转移 | 不能，分别补本地确认及人工证据核对 | 时间邻近与执行历史不是业务状态断言 |

主契约规定新能力的语义；精确 JSON schema、命令名和预算仍待实施前确定。本文不再列出另一套候选 API。
