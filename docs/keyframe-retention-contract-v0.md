> **状态（2026-10-05 更新）：核心条款已实现并完成首轮验收**——捕获身份（session/daemon/代次/seq）、
> per-frame 尺寸（`fw/fh`，ROI 换算不再用全局尺寸）、L0 双区缓存 + 字节预算、显式升格（tmp+rename、

>

>
> 文中源码行号对应重构前基线 commit `85dae0e`（2026-10-03 核查），仅用于定位；结论不依赖行号，重构后需重定位。

> 需求来源：state-plan v0 的 evidence 引用（`kf:xxxx`）此前在工具侧没有落点。运行工具（maafw-live）有实时观察底座——常驻 daemon：连续采样 + 变化检测 + 环形缓冲——但环内只保留降采样小图，原图不留存；**当事后决定保留某帧时，那次捕获的原图往往已经不存在**（现调 screencap 拿到的是另一个时刻，对消失的一次性状态没有帮助）。
>
> 本契约只定一件事：**如何把短期实时信息，选择性地留存为可跨工作会话复用的开发证据（以 L0 观测帧为载体）**。沿用既有架构裁决（"持续观察、同源关联"；独立轨迹记录层已被否决——"agent 边探索边写，写下的 pipeline 就是记录"），因此这是**在现有观测流上补关联和留存**，不造第二套采集链，不造资产平台，不重建轨迹系统。

## 0. 责任边界

| 层 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| maafw-live（生产端） | 采集事实、执行动作、输出节点事件、导出/留存观测帧 | 不判断业务上完成了哪个计划状态 |
| harness 对接层（关键帧工具） | 进程生命周期、升格决策与登记、观测与计划的关联 | 不建立第二套设备采集链 |
| state-plan | 需求、状态与转移、实现映射、进度、证据引用 | 不复制帧流、运行日志、设备会话 |

> **与 MaaEvidenceKit（MEK）的边界**：MEK 管**诊断证据**——从日志、项目文件与仓库文档提取确定性事实（`maa-evidence/v1`，evidence ID 由来源定位决定），服务 issue 分析；本契约管**观测帧**——设备原图的捕获与留存（`kf:` ID 为关键帧库序号，携带会话 / 分辨率 / 帧序身份），服务 pipeline 编写。两者不共享 schema、不互相索引；将来若需关联（如诊断报告引用某帧），按完整 ID 单向引用，不合并。本契约内"证据"一词除引用 state-plan 的 `evidence` 语义外，一律指留存帧。

## 1. 三项保证

**采得到**（覆盖，不承诺完备）

- 现状：daemon 连续采样（活跃 8fps / 静默约 1Hz，`framed.mjs:195,440`）；输入动作不触发即时抓帧或提频（`framed.mjs:630-653`）。
- 契约要求：输入动作边界（前、后）各保留一张原图进 L0 缓存（§2）——窄增强，落在现有 input / 节点事件出口；可选增强（不门禁）：变化后短时连拍、输入后短时提频。
- 明确不承诺：所有瞬态必被捕获。低频阶段的一次性弹窗仍可能漏采；单纯增大缓存不解决漏采。漏采的状态就是没有证据——state-plan 侧按 guessed 处理，这是既有的诚实语义。

**留得住**（升格）

- 现状：环形缓冲只存降采样小图（默认长边 480、120 张，`framed.mjs:195,383-390`）；流式路径上原图解码后即弃（`framed.mjs:429-432`）；`screencap` 能拿原图但那是"另一个时刻"。
- 契约要求（工具侧新增的窄能力）：
  1. 与预览环并行的 **L0 原图有界缓存**，分两区：**滚动区**——最近 K 张原图（默认建议 16），保证"刚看到就能留"；**锚区**——change/stable 事件锚点帧、动作边界帧、run 起止帧（默认建议 32）。各自 FIFO，总容量有界可配。
  2. **升格**：从 L0 缓存取原图落盘进本地关键帧库 + 登记（§4），返回 id / path / sha256 / 保留状态。
  3. **保留状态必须显式**：元数据还在 ≠ 像素可读。L0 已淘汰时升格如实报失败，允许降级导出小图作参考帧（§6）。
- 不做：全量永久保存、自动判定"哪些帧重要"（升格决策在 harness/agent/人）、独立资产平台。

**对得上**（引用与坐标）

- 留存记录必须携带（§4）：会话/连接代次与设备来源、捕获时间与捕获时帧序、**捕获时控制器分辨率**、小图尺寸与缩放关系、持久文件定位、内容完整性标识。
- 契约动机即当时的现状缺陷：历史帧 ROI 换算用当前全局控制器尺寸而非该帧捕获时尺寸，重连/改分辨率后旧帧会被错误裁剪（**已修**：每帧携带 `fw/fh`，换算用捕获时尺寸，R1 验收通过）。坐标元数据是留存帧可用（可复核）的前提，不是锦上添花。

## 2. 图像层级（保留哪种图像）

| 层 | 是什么 | 用途 | 可否作 state 证据本体 |
| --- | --- | --- | --- |
| L0 原图 | 控制器分辨率、捕获时刻的整帧 | 唯一证据本体；模板/测试图的升格源 | ✅ |
| L1 预览小图 | 环内降采样帧（默认长边 480） | 人看、变化检测、粗对齐；识别单测可接受其作输入（结果须标注来源尺寸） | ❌ 只作参考帧 |
| L2 派生图 | 从 L0 脱敏裁剪、语义命名后的模板图、测试图 | 提交进仓库（state-plan §5 升格路径） | 本身即交付物 |

规则：

- **升格仅限 L0**。L0 已淘汰 → 只能导 L1 参考帧，state 证据按 unverified 计。
- L0 原图永不修改；脱敏裁剪只产生 L2 派生物。
- 关键帧库内 L0 以"文件 + 登记记录"存在，不进 git（沿用 state-plan 存储分层：体积无控 + 账号隐私 + 过程资产）。

## 3. 什么情况下留存

自动候选（生产端/对接层，进 L0 缓存即可，**不等于升格**）：

- change / stable 事件锚点帧；
- 输入动作边界帧（前、后）；
- run 起止帧、节点 ok/fail 事件时刻帧。

显式升格（决策在 agent / 人）：

- agent 在动线中认定某帧是状态证据（观测到新 state、异常弹窗、不可复现状态）→ 指定 seq 或"最新帧"升格；
- 升格后引用写进 state-plan 的 evidence。

容量淘汰：L0 缓存 FIFO，淘汰即不可升格——动线纪律是**"看到即升格，不攒到最后"**。

## 4. 如何唯一引用

- **kf ID 由关键帧库 manifest 分配**：建议 `kf:<库UUID>:<零填充序号>`。库内序号单调递增、永不复用；库 UUID 创建后持久保存，复制库保留身份，新建库生成新身份。调用方把完整 ID 当不透明字符串，不解析其中序号。
- 裸 `kf:0142` 只可作展示简称，不能作为跨库持久引用：两个库都可能有 0142，哈希若只存各自 manifest 内也不能防止误指向。库副本在 v0 按单写者管理，不支持副本独立写入后自动合并；发现同 ID 对应冲突内容时必须报错，不能任选一份。
- manifest 每条记录（关键帧库本地，如 `frames/manifest.json`，与 L0 文件同库）：

| 字段 | 说明 |
| --- | --- |
| schema | manifest 版本；未知版本返回 unsupported，不默认为当前版 |
| id | 完整 `kf:<库UUID>:<序号>`；示例值不代表实际回执 |
| file | L0 文件的库内相对路径，不以本机绝对路径决定身份 |
| sha256 | PNG 文件字节的完整性摘要；不是感知 hash，也不独自证明来源真实性 |
| session | daemon 实例 UUID、连接代次与目标来源（kind / target）；地址 / hwnd 只是当时定位，不是永久设备身份 |
| capturedAt | 捕获时间，ISO 8601 带时区；同进程排序另用 captureSeq |
| captureSeq | 捕获时帧序，与 session / 连接代次联合定位，不单独作为帧身份 |
| ctrlW / ctrlH | **捕获时**控制器图像实际尺寸；控制器基准配置同时留档 |
| smallW / smallH / scale | 当时小图尺寸与缩放关系；无小图则明确为空，不借用最新帧数据 |
| source | change / stable / action-before / action-after / run-start / run-end / node-ok / node-fail / explicit |
| note | 脱敏语义说明，不含账号信息 |

- **关联强度（建议术语）**：
  - `bound`：该留存帧就是引擎识别所用的那张图——**当前节点事件接口不提供，不许冒称**；
  - `adjacent`：时间邻近关联——节点事件记录的是回调时最新帧序（`framed.mjs:550-565`），属于此类。
  - 关联强度属于“事件与图像的关系”，不是图片文件的属性，也不等于业务验证结果。当前节点事件关联按 adjacent 处理；转移级引用若只有邻近帧，只能作为线索，不能证明动作导致了目标状态。

### 4.1 最小操作语义（名称及传输格式待定）

- **留存选定捕获**：输入 session / 连接代次 / captureSeq；若选择“最新”，必须在接受请求时固定具体捕获身份。已淘汰则失败，绝不重新截图或改取更新帧冒充指定帧。同一捕获与图像规格的重试可以返回原对象，不得改写旧 ID 的含义。
- **发布留存结果**：先固定像素并写 L0 文件，再发布 manifest 记录；半写文件、磁盘失败、配额不足不能返回成功引用。路径由本地库管理，不能覆盖 preview 或既有留存。
- **按完整 ID 帧解析**：不依赖 daemon 存活。至少返回 available / missing / corrupt / unsupported；仅 available 提供经过完整性检查的图像路径。missing 表示本机不可复核，不表示历史从未观测。
- **保留与清理**：已升格对象不随 L0 热缓存淘汰，不被后台 TTL/LRU 静默删除。配置本地库配额；满额时拒绝新增留存并报告，由用户处理清理或扩容。显式删除后保留缺失诊断，不自动重用 ID。
- **隐私**：设备地址、完整来源和图像留在本地；计划只登记完整 ID 与脱敏说明。复制本地库、把 L2 提交仓库、向外部服务上传是不同操作，不自动串联。


## 5. 坐标如何解释

- 坐标 / ROI 必须声明所属图像空间。控制器图像指框架截图链路交付的图像，不一定是设备物理屏幕原始分辨率；L1 的识别 box 属于小图空间，不能直接抄成 pipeline ROI。
- 工具侧要求：历史帧 ROI 换算必须用 per-frame 尺寸（**已实现并验收**：`frame_get` 与变化区域换算均用该帧捕获时尺寸）。
- 与 state-plan 的 `baseline: 720` 的关系：baseline 从项目 controller 配置获取，不替代每帧实际尺寸。换算是待补能力，不能说当前识别测试已经自动完成；缺少转换依据时拒绝用于坐标生成。
- L2 记录来源及裁剪 / 缩放变换。脱敏或裁剪可能去掉识别上下文，必须重核 hits / box 断言；不原地修改 L0，不继承原图的全部验证结论。

## 6. 何时不可复核（降级阶梯）

| 情形 | 判定 |
| --- | --- |
| 引用无对应 manifest 记录 / 文件丢失 | unverified |
| sha256 不匹配（文件损坏或被改） | unverified |
| 元数据不全（缺 ctrlW/ctrlH 或 session） | unverified（用于 ROI / 识别测试时；可作一般参考） |
| 只有 L1 小图（L0 已淘汰） | 参考帧，不可作 state 证据本体 |
| 节点事件关联未标注强度 | 一律按 adjacent 计 |

本文的“可复核”只表示**文件在、哈希对、元数据全**，不表示 state 已确认、识别通过或任务成功。统一用 available 表示解析可用，避免与 state-plan 的 tested 混淆；missing / corrupt / unsupported 在计划投影中可统一提示“当前不可复核”，但保留具体原因。

留存帧不可复核不抹去历史观测和实现进度；只是不能继续以它为当前落笔依据。需补观测或恢复像素后核对。L1-only 按本文较严格的策略只作为参考，不得上采样冒充 L0。

动线纪律（非缺陷，写入防误用）：

- **单会话单控制器**：一次性命令每次 spawn 自己的 daemon，与面板 daemon 并存 = 同设备两控制器互扰（定案红线）。交互探索用 repl，验证用一次性 `run --project`，不并发。
- **一次性 run 不起流，seq 恒为 0**：帧序对齐只在 repl / client 订阅路径有效。state-plan 证据引用不依赖 seq（§4 captureSeq 仅考古）。
- **长流程分段跑**：单次 run 超时上限 300s，按 subflow 分段——与滚动开发动线天然一致。

**消费注意（现有接口，核查基线）**

新能力落地前，消费现有接口注意：

- 优先接 `maafw-live/client` 的 `spawnDaemon`、`call`、`subscribe`，不要解析会截断长结果的 REPL 文本。
- frame 订阅回调拿到 `{seq, t, hash, diff, w, h}`；hash 是感知哈希，不是文件 SHA-256。
- frame_get 返回 `{ok, path, bytes, w, h, seq, t, diff}`，导出的是小图或其裁剪。
- reco_test 返回结果列表，每项有 param / ms / ok / detail；输入小图时 box 属于小图空间，不自动等于 pipeline 坐标。
- run 返回 `{ok, record}`，业务成功在 `record.ok`；外层调用完成不等于任务成功。
- 节点 seq 可被后续回调更新；startSeq 不是严格的开跑前截图，framesCaptured 是进程累计值，不据此计算本次无损覆盖。
- 传输回复与 data 内有不同层级的 ok；业务失败不一定让客户端 Promise reject。

## 8. 对 state-plan v0 的落点

1. `frames:` 定位为证据引用登记，完整 ID 与本契约对齐；不复制本地 manifest，不把原图缓存描述为已实现。
2. checkpoint 仅表示开发断点，由 agent 维护。设备最后确认位置另存本地，至少含目标 / session、state、证据与确认时间；**record.nodes 是执行记录，不是设备位置断言**。新动作、画面变化、重连、重启或人工接管后，操作前重新观测；歧义允许 unknown。
3. tested 必须结合验证对象、范围、实际结果及被测实现指纹；任务级 `record.ok` 是流程结果的一项输入，不自动升级沿途所有 state。静态识别、节点、局部流程和端到端分别说明；实现变化后提示待复验。
4. transitions 可选 `evidence` 在 v0 仅辅助人工核对，不自动门禁；既有“观测源状态、动作目标、动作后实际出口才落笔”的护栏不放松。只有 adjacent 帧不能独自证明边，多出口须逐项核对。选定动作回执及转移观测记录 schema 待后续定义，不重建全量轨迹层。
